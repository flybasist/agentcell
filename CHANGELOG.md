# CHANGELOG

## v0.2.0 — Своя VM на macOS, плагины и плагин kind (2026-11-08)

### Новое

- **macOS: собственная VM Colima `agentcell`.** В неё смонтированы только папки из
  конфига `~/.config/agentcell/config` (`PROJECT_DIR`, обязательно) и хранилище; домашней
  папки нет. Скрипт запуска сам стартует остановленную VM и при каждом запуске проверяет, что
  домашняя папка в VM не видна. Ваша Colima и docker-контекст не меняются.
- **Команды VM:** `--vm-status`, `--vm-stop`, `--vm-apply`.
- **Параллельная работа:** сколько угодно сессий одновременно (в том числе в одной папке);
  одновременный старт остановленной VM безопасен (замок); обычный `docker compose` и другие
  проекты в вашей Colima `default` не затрагиваются.
- **Пайпы:** данные из стандартного ввода доходят до claude (`cat файл | agentcell -p ...`).
- **Опция `BLOCK_HOST_ACCESS=1`** (по умолчанию выключена): закрывает контейнерам доступ к
  сервисам на localhost Мака правилом межсетевого экрана в VM.
- **Проверки конфига:** отказ при слишком широких, «секретных» (без учёта регистра) и
  пересекающихся папках (Colima не принимает пути, один из которых начинается с другого);
  ошибки с готовыми командами.
- **Плагины:** необязательные возможности подключаются при установке
  (`./scripts/install.sh --with <имя>`, `--without <имя>`) и включаются в сессии своими
  переменными `AGENTCELL_<ПЛАГИН>_*`. У плагина свой манифест (платформы, несовместимость,
  аргументы сборки образа), свой файл настроек и три функции (`check`, `prepare`, `status`).
  Контейнер плагин меняет только через сеть и переменные окружения: монтирования и
  привилегии ему недоступны. Правила и как написать свой: `docs/PLUGINS.md`.
- **Плагин kind (macOS):** агент получает доступ к одному локальному kind-кластеру в VM
  agentcell (`AGENTCELL_KIND_CLUSTER=<имя>`): ServiceAccount с правами admin в namespace
  `agent`, Pod Security `baseline`, отдельный kubeconfig на кластер, срок токена в настройках
  плагина. cluster-admin — только `AGENTCELL_KIND_ADMIN=1` на одну сессию. Перед выдачей
  прав плагин ждёт готовности кластера (после `kind create cluster` и после старта VM).
  Описание:
  `docs/plugins/kind.md`.
- **kubectl в образе только для плагина kind** (версия закреплена, `KUBECTL_VERSION`,
  проверка sha256, метка на образе).

### Изменено

- macOS: запуск возможен только внутри папок `PROJECT_DIR`; `AGENTCELL_ALLOW_ANY_DIR`
  теперь только для Linux.
- Сообщения скрипта запуска идут в stderr.
- `install.sh` на macOS создаёт шаблон конфига и VM, образ собирается в VM agentcell; умеет
  ставить и убирать плагины.
- Linux: задуманное поведение прежнее, но общий код (скрипт запуска, `install.sh`,
  Dockerfile) менялся, а на Linux версия v0.2.0 **не проверялась**. Проверка запланирована,
  после неё этот пункт будет обновлён.

## v0.1.0 — Первая версия (2026-10-31)

### Что есть

- **Скрипт запуска `scripts/agentcell`:** `docker run` с двумя монтированиями (проект в
  `/workspace`, хранилище в `/home/agent`), запуск не от root, `--cap-drop=ALL`,
  `no-new-privileges`, `--rm`, `--init`.
- **Защита от широкого монтирования:** отказ при запуске из домашней папки и из `/`
  (отключается переменной `AGENTCELL_ALLOW_ANY_DIR=1`).
- **Режимы:** интерактивная сессия, `-p "задача"` без диалога, `--shell` (bash внутри
  контейнера); запуск без терминала (cron, пайпы) поддерживается.
- **Вход:** подписка Claude (интерактивно) или `ANTHROPIC_API_KEY` с хоста
  (передаётся по имени, не попадает в аргументы и образ).
- **Установка `scripts/install.sh`:** сборка образа и установка команды `agentcell` в `~/bin`;
  повторный запуск обновляет Claude Code, версию можно закрепить через
  `CLAUDE_CODE_VERSION`.
- **Образ `Dockerfile`:** Node.js 24 и Claude Code из npm, версия вморожена в образ.
- **Документация:** `docs/` — быстрый старт, устройство, безопасность, сторонние компоненты.
- **Платформы:** macOS (Docker и Colima) и Debian 13; скрипты совместимы с bash 3.2.
