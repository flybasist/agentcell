# Устройство agentcell

Что где лежит и какие условия нельзя нарушать — см. [README.md](README.md) этой папки.

## 1. Общая картина

**macOS:**

```
Мак
  ├─ ~/.config/agentcell/config   <- папки проектов и ресурсы VM (в VM не попадает)
  ├─ ~/.config/agentcell/plugins  <- установленные плагины и их настройки (в VM не попадают)
  ├─ ~/.config/agentcell/state    <- хранилище: вход в аккаунт, настройки
  └─ VM Colima "agentcell"        <- видит только папки PROJECT_DIR и хранилище
       ├─ контейнер agentcell
       │    /workspace    <- папка, из которой запущен agentcell
       │    /home/agent   <- хранилище
       └─ кластеры плагинов <- например, kind-кластер (плагин kind), создаётся вручную
```

**Linux (Debian 13):**

```
Компьютер
  └─ Docker
       └─ контейнер agentcell
            /workspace    <- папка, из которой запущен agentcell
            /home/agent   <- хранилище (~/.config/agentcell/state)
```

Контейнер видит компьютер в двух точках. Больше ничего: ни домашней папки, ни SSH-ключей,
ни сокета Docker.

## 2. Собственная VM на macOS

На macOS Docker работает внутри виртуальной машины Colima. Обычная Colima (профиль
`default`) монтирует в VM всю домашнюю папку на запись. Контейнер её не видит, но всё,
что окажется «внутри VM» (побег из контейнера через уязвимость или привилегированный под
в кластере плагина), увидит `~/.ssh`, `~/.kube`, `~/.aws` и все проекты.

Поэтому у agentcell своя VM — профиль Colima `agentcell` (docker-контекст
`colima-agentcell`). В неё смонтированы только:

- папки из `PROJECT_DIR` в конфиге `~/.config/agentcell/config`;
- хранилище `~/.config/agentcell/state`.

Домашней папки в VM нет. Ваша Colima `default` и ваш текущий docker-контекст не
используются и не меняются: все команды docker скрипт запуска отправляет в контекст
`colima-agentcell` явно (`docker --context ...`), а VM стартует с `--activate=false`.

**Почему список папок, а не только текущая папка.** Colima не умеет добавлять
монтирования на лету: новая папка = перезапуск VM (обычно до минуты), при котором обрываются
другие сессии и перезапускаются кластеры плагинов. Со списком папок переход между проектами
мгновенный, параллельные сессии и cron не мешают друг другу. Насколько широк список,
решает пользователь: можно перечислить хоть каждый проект отдельно.

**Конфиг** — строки `КЛЮЧ=значение`, читается построчно (не выполняется как скрипт).
Значения по умолчанию для `PROJECT_DIR` нет. Скрипт запуска отказывается работать, если в
списке `/`, `/Users`, домашняя папка или папка, которая содержит `~/.ssh`, `~/.kube`,
`~/.aws`, `~/.gnupg`, `~/.docker`, `~/.config`, `~/.colima`, `~/.lima`, `~/Library` (или
лежит внутри них). Эти имена сравниваются без учёта регистра: файловая система Мака по
умолчанию его не различает. Папки не должны пересекаться друг с другом и с хранилищем:
Colima сравнивает пути как обычные строки, поэтому `~/src` и `~/src2` для неё уже
пересекаются (как и вложенные папки).

**Применение конфига.** При `agentcell --vm-apply` скрипт запуска сохраняет настройки VM в
`~/.config/agentcell/vm-applied`. При каждом запуске он сравнивает их с конфигом: если
конфиг изменили, а не применили, — ошибка с подсказкой. Сам скрипт VM не
перезапускает, чтобы не оборвать другую сессию.

**Доступ контейнеров к Маку.** По умолчанию контейнер из VM может обращаться к хосту по адресу
`host.lima.internal` (192.168.5.2), то есть к сервисам на localhost Мака. Опция
`BLOCK_HOST_ACCESS=1` (`vm_block_host_access`) ставит в VM правило `iptables -I DOCKER-USER
-d <адрес хоста> -j REJECT` после каждого старта VM: оно не переживает перезапуск. Опция входит в
список настроек, по которым `--vm-apply` решает, что конфиг изменился.

**Одновременный старт.** Проверка и старт VM выполняются под замком (`~/.config/agentcell/vm.lock`,
создаётся командой `mkdir`): если два запуска стартуют одновременно, второй ждёт первого, а не
пытается поднять ту же VM. Замок с номером процесса: если процесс завершился, не сняв замок,
наступивший запуск забирает его.

**Проверка по факту.** При каждом запуске скрипт запуска через `colima ssh` проверяет, что
папка `~/Library` Мака внутри VM не видна. Она есть у любого Мака и никогда не
монтируется, поэтому её видимость означает, что в VM смонтирована домашняя папка
(например, профиль пересоздали руками). Тогда запуск отменяется.

**Жизненный цикл.** VM стартует при первом запуске `agentcell` (или `install.sh`) и
работает, пока Мак не перезагрузят или не выполнят `agentcell --vm-stop`. Автоостановки
нет: она обрывала бы параллельные сессии и перезапускала кластеры плагинов. Остановленную VM
следующий запуск поднимает сам, без вопросов.

## 3. Хранилище

Внутри контейнера `HOME=/home/agent`, а это папка `~/.config/agentcell/state` на компьютере.
В ней Claude Code хранит вход в аккаунт, настройки и кэш; сюда же можно положить `git config`
(через `agentcell --shell`). Это не `~/.claude` вашего компьютера: Claude Code, установленный
на хосте, живёт отдельно и контейнером не затрагивается.

Папка создаётся с правами `700`, потому что в ней лежит токен входа. Хранилище общее для
всех проектов: войти достаточно один раз. Конфиг лежит рядом, но не внутри хранилища,
поэтому агент его не видит и изменить не может.

## 4. Что происходит при установке и запуске

**Установка и обновление** (`scripts/install.sh`):
1. Разбор `--with` и `--without`: плагин существует, в его коде нет синтаксических ошибок,
   он поддерживает эту систему и не конфликтует с установленными. Затем плагины копируются
   в `~/.config/agentcell/plugins/<имя>/` (настройки не перезаписываются) или удаляются.
2. Только macOS: если конфига нет — создаётся шаблон, установка останавливается до
   заполнения `PROJECT_DIR`.
3. Только macOS: `agentcell --vm-apply` (из репозитория) создаёт VM или приводит её к
   конфигу. Если VM уже соответствует конфигу, она не перезапускается.
4. Linux: проверка, что Docker доступен.
5. `docker build --pull --no-cache` собирает образ (на macOS — в VM agentcell: у каждой VM
   своё хранилище образов); в сборку добавляются аргументы из манифестов установленных
   плагинов (`IMAGE_ARGS`). `Dockerfile` передаётся через stdin, потому что в образ ничего
   из репозитория не копируется.
6. Скрипт `scripts/agentcell` копируется в `~/bin` (или в `BIN_DIR`).

В образе нет секретов, его можно переносить между компьютерами.

**Запуск** (`scripts/agentcell`):
1. Создание папки хранилища.
2. macOS: чтение и проверка конфига; VM существует, настроена по конфигу, запущена
   (если остановлена — старт); проверка по факту, что домашней папки в VM нет.
3. Linux: проверка, что Docker доступен.
4. Проверка, что образ собран.
5. Проверка папки: macOS — она внутри одной из `PROJECT_DIR`; Linux — это не `/` и не
   домашняя папка.
6. Сборка списка аргументов `docker run`.
7. Плагины: загрузка установленных, затем `check` у каждого и `prepare` у каждого
   (раздел 6). Плагин, не включённый в этой сессии, ничего не делает.
8. Запуск через `exec`.

## 5. Чем ограничен контейнер

| Флаг | Эффект |
|---|---|
| `--user $(id -u):$(id -g)` | процесс работает под вашим пользователем, а не root; файлы в проекте остаются вашими |
| `--cap-drop=ALL` | процесс лишён дополнительных прав Linux |
| `--security-opt no-new-privileges` | процесс не может получить больше прав, чем у него есть (например, через setuid-программы) |
| `-v ... :/home/agent`, `-v ... :/workspace` | единственные папки компьютера, видимые контейнеру |
| `--rm` | после выхода контейнер пропадает |
| `--init` | завершает дочерние процессы, чтобы не копились зомби в долгих запусках |
| `--context colima-agentcell` (macOS) | контейнер запускается в VM agentcell, а не в вашей Colima |

Что изоляция не закрывает и как её усилить, см. [SECURITY.md](SECURITY.md).

## 6. Плагины

Ядро делает одно: запускает Claude Code в контейнере с одной папкой. Что нужно не каждому,
подключается плагинами (сейчас один: [kind](plugins/kind.md)). Подробно — в
[PLUGINS.md](PLUGINS.md); здесь только устройство.

- **Где лежат.** Плагин — папка `~/.config/agentcell/plugins/<имя>/` с манифестом
  `plugin.conf`, кодом `plugin.sh` и настройками `config`. Её создаёт
  `./scripts/install.sh --with <имя>`. Установленный плагин включён.
- **Как загружаются.** `load_plugins` в `scripts/agentcell` читает манифесты, пропускает
  плагины, которые не поддерживают эту систему, отказывает при несовместимых плагинах и
  загружает код командой `source`. У каждого плагина должны быть три функции: `<имя>_check`,
  `<имя>_prepare`, `<имя>_status`.
- **Когда вызываются.** При каждом запуске сначала `check` у всех плагинов (они ничего не
  меняют), потом `prepare` у всех. Плагин сам выходит, если в этой сессии он не включён
  (его переменная `AGENTCELL_<ПЛАГИН>_*` не задана). `status` вызывается из `--vm-status`.
- **Что может плагин.** Менять контейнер только через `plugin_add_network` и
  `plugin_add_env`; читать свои настройки через `plugin_read_config`. Монтирования,
  привилегии и другие флаги docker недоступны: изоляция остаётся такой, какой её описывает
  раздел 5.
- **Образ.** Если плагину нужен инструмент, манифест передаёт сборке аргумент
  (`IMAGE_ARGS`), в `Dockerfile` есть соответствующий `ARG`, а на образ ставится метка,
  которую плагин проверяет перед запуском.

## 7. Запуск без терминала

Флаг `-t` добавляется к `docker run`, только если и ввод, и вывод — терминал. Поэтому
`agentcell -p "..."` работает из cron, systemd и пайпов. Сообщения самого скрипта идут
в stderr и не смешиваются с ответом claude. В скрипте нет вопросов к пользователю:
всё, что требует решения человека, заканчивается ошибкой с готовой командой.

Данные из пайпа (`cat файл | agentcell -p "..."`) доходят до claude целыми: все вызовы colima,
которые могли бы прочитать стандартный ввод (`colima ssh` забирает его весь), запускаются с
`</dev/null`.

## 8. Почему так

**Изоляция во флагах запуска, а не в образе.** Её можно менять, не пересобирая образ.

**Claude Code ставится из npm в образ при сборке.** Установка воспроизводима, версия
закрепляется через `CLAUDE_CODE_VERSION`. Установщик, который скачивает программу в
`$HOME`, не подошёл: `$HOME` у нас — это смонтированное хранилище, установка попала бы
туда, версия перестала бы быть вмороженной, а хранилище разрослось бы.

**Плагины загружает ядро, а не отдельные скрипты.** Отдельный скрипт-обёртка (например,
`agentcell-kind`) вызывал бы ядро сам, и два таких скрипта нельзя было бы использовать
одновременно. Загруженный плагин работает в процессе ядра, пользуется его функциями и
видит VM уже запущенной. Цена: ошибка плагина может сломать запуск, поэтому установка
проверяет код плагина (`bash -n`), а имена функций плагина начинаются с его имени.

**Плагин не может ослабить изоляцию.** Контейнер он меняет только через две функции ядра
(сеть и переменные). Любой флаг docker, который нарушил бы условия из `docs/README.md`
(лишнее монтирование, привилегии), недоступен. Если будущему плагину понадобится что-то
ещё, это осознанное изменение ядра, а не молчаливая возможность.

**Образ без лишних инструментов.** Инструмент плагина (kubectl для kind) ставится только по
аргументу сборки: версия закреплена (`KUBECTL_VERSION`), архитектура берётся у системы
образа (`dpkg --print-architecture`), файл сверяется с контрольной суммой.

**Самообновление отключено** (`DISABLE_AUTOUPDATER=1`): программа лежит в образе, контейнер
запускается не от root и удаляется после выхода, так что обновление внутри него бессмысленно.
Обновляется Claude Code только пересборкой образа.

**Пересборка с `--no-cache`.** Без этого Docker взял бы из кэша старый слой с установкой
Claude Code, и версия не изменилась бы.

**Защита от запуска не из той папки.** Главный риск идеи «виден только проект» — запустить
не из той папки. На Linux скрипт отказывается работать из `~` и `/` (обход — осознанный,
через `AGENTCELL_ALLOW_ANY_DIR=1`). На macOS запуск возможен только внутри `PROJECT_DIR`:
VM другие папки не видит.

**Одна кодовая база для macOS и Linux.** Различия собраны в нескольких местах скрипта запуска
(`is_mac`), все вызовы docker идут через функцию `dkr`. Скрипты совместимы с bash 3.2,
который установлен в macOS.

**Режим `--shell` и работа без терминала.** Они нужны для двух типичных задач: зайти в тот
же контейнер руками (настроить git, посмотреть, что внутри) и запускать задачи из скриптов.
Отдельный образ для этого не нужен.

## 9. Что нужно для работы

- macOS 13+ с Colima и Docker CLI (`brew install colima docker`) либо Debian 13 с пакетом
  `docker.io`. Плагин kind требует ещё `kind` ([docs/plugins/kind.md](plugins/kind.md)).
- Доступ в интернет: при сборке образа (npm; dl.k8s.io, если установлен плагин kind) и во
  время работы (API Anthropic).
- macOS: память под VM agentcell (по умолчанию 6 ГиБ) — пока VM запущена, она занята.
