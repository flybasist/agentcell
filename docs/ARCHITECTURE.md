# Устройство agentcell

Что где лежит и какие условия нельзя нарушать — см. [README.md](README.md) этой папки.

## 1. Общая картина

```
Компьютер (macOS или Debian 13)
  └─ Docker (на macOS — внутри виртуальной машины Colima)
       └─ контейнер agentcell
            /workspace    <- папка, из которой запущен agentcell
            /home/agent   <- хранилище (~/.config/agentcell/state)
            claude        <- установлен в образ при сборке
            прочее        <- файлы образа, на ваш компьютер не влияют
```

Контейнер видит компьютер в двух точках. Больше ничего: ни домашней папки, ни SSH-ключей,
ни сокета Docker.

## 2. Хранилище

Внутри контейнера `HOME=/home/agent`, а это папка `~/.config/agentcell/state` на компьютере.
В ней Claude Code хранит вход в аккаунт, настройки и кэш; сюда же можно положить `git config`
(через `agentcell --shell`). Это не `~/.claude` вашего компьютера: Claude Code, установленный
на хосте, живёт отдельно и контейнером не затрагивается.

Папка создаётся с правами `700`, потому что в ней лежит токен входа. Хранилище общее для
всех проектов: войти достаточно один раз.

## 3. Что происходит при установке и запуске

**Установка и обновление** (`scripts/install.sh`):
1. Проверка, что Docker доступен.
2. `docker build --pull --no-cache` собирает образ; `Dockerfile` передаётся через stdin,
   потому что в образ ничего из репозитория не копируется.
3. Скрипт `scripts/agentcell` копируется в `~/bin` (или в `BIN_DIR`).

В образе нет секретов, его можно переносить между компьютерами.

**Запуск** (`scripts/agentcell`):
1. Проверка, что Docker доступен и образ собран.
2. Проверка папки: если это `/` или домашняя папка — отказ.
3. Создание папки хранилища.
4. Сборка списка аргументов `docker run` и запуск через `exec`.

## 4. Чем ограничен контейнер

| Флаг | Эффект |
|---|---|
| `--user $(id -u):$(id -g)` | процесс работает под вашим пользователем, а не root; файлы в проекте остаются вашими |
| `--cap-drop=ALL` | процесс лишён дополнительных прав Linux |
| `--security-opt no-new-privileges` | процесс не может получить больше прав, чем у него есть (например, через setuid-программы) |
| `-v ... :/home/agent`, `-v ... :/workspace` | единственные папки компьютера, видимые контейнеру |
| `--rm` | после выхода контейнер пропадает |
| `--init` | завершает дочерние процессы, чтобы не копились зомби в долгих запусках |

Что изоляция не закрывает и как её усилить, см. [SECURITY.md](SECURITY.md).

## 5. Запуск без терминала

Флаг `-t` добавляется к `docker run`, только если и ввод, и вывод — терминал. Поэтому
`agentcell -p "..."` работает из cron, systemd и пайпов.

## 6. Почему так

**Изоляция во флагах запуска, а не в образе.** Её можно менять, не пересобирая образ.

**Claude Code ставится из npm в образ при сборке.** Установка воспроизводима, версия
закрепляется через `CLAUDE_CODE_VERSION`. Установщик, который скачивает программу в
`$HOME`, не подошёл: `$HOME` у нас — это смонтированное хранилище, установка попала бы
туда, версия перестала бы быть вмороженной, а хранилище разрослось бы.

**Самообновление отключено** (`DISABLE_AUTOUPDATER=1`): программа лежит в образе, контейнер
запускается не от root и удаляется после выхода, так что обновление внутри него бессмысленно.
Обновляется Claude Code только пересборкой образа.

**Пересборка с `--no-cache`.** Без этого Docker взял бы из кэша старый слой с установкой
Claude Code, и версия не изменилась бы.

**Защита от запуска из `~` и `/`.** Главный риск идеи «виден только проект» — запустить не
из той папки. Поэтому скрипт по умолчанию отказывается. Обход — осознанный, через
`AGENTCELL_ALLOW_ANY_DIR=1`.

**Один код для macOS и Linux.** Различаются только подсказки об ошибках (Colima на macOS,
группа `docker` на Linux). Скрипты совместимы с bash 3.2, который установлен в macOS.

**Режим `--shell` и работа без терминала.** Они нужны для двух типичных задач: зайти в тот
же контейнер руками (настроить git, посмотреть, что внутри) и запускать задачи из скриптов.
Отдельный образ для этого не нужен.

## 7. Что нужно для работы

- macOS 13+ с Docker CLI и Colima либо Debian 13 с пакетом `docker.io`.
- Доступ в интернет: при сборке образа (npm) и во время работы (API Anthropic).
- Colima по умолчанию пробрасывает в виртуальную машину только домашнюю папку, поэтому
  проекты должны лежать внутри неё (или монтирование Colima нужно настроить).
