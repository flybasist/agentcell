# Документация agentcell

agentcell запускает Claude Code в Docker-контейнере, который видит только одну папку проекта
и небольшое хранилище для входа в аккаунт. На macOS контейнер работает в собственной VM
Colima, которая не видит домашнюю папку. Необязательные возможности (например, доступ к
локальному kind-кластеру) подключаются плагинами. Это утилита из скрипта запуска, скрипта
установки, Dockerfile и плагинов.

## Для ИИ-агентов и разработчиков

Эта страница — точка входа. Читайте её первой, затем нужный файл из оглавления.
Не сканируйте весь репозиторий заново: карта ниже достаточна.

### Что где лежит

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ: `node:24` + `npm install -g @anthropic-ai/claude-code`, `ENTRYPOINT ["claude"]`; kubectl (версия закреплена, sha256) только при `WITH_KUBECTL=1` (плагин kind). Файлы проекта в образ не копируются. |
| `scripts/agentcell` | Скрипт запуска на хосте (копируется в `~/bin`): проверки, на macOS — управление VM Colima `agentcell` (`--vm-*`), загрузка плагинов (`load_plugins`) и их функции, затем `docker run` с изоляцией. |
| `scripts/install.sh` | Плагины (`--with`, `--without`), на macOS шаблон конфига и `agentcell --vm-apply`, затем сборка образа (`--pull --no-cache`, с аргументами плагинов) и установка команды `agentcell`. Он же — обновление. |
| `plugins/<имя>/` | Плагины: манифест `plugin.conf`, код `plugin.sh`, пример настроек `config.example`. Сейчас один: `kind`. |
| `README.md` | Краткое описание для человека. |
| `CHANGELOG.md` | История изменений. |
| `docs/` | Вся остальная документация. Должна всегда соответствовать коду. |

Файлы на компьютере пользователя: `~/.config/agentcell/config` (конфиг, macOS),
`~/.config/agentcell/vm-applied` (с какими настройками запущена VM),
`~/.config/agentcell/plugins/<имя>/` (установленный плагин и его настройки `config`),
`~/.config/agentcell/state` (хранилище = `/home/agent`).

### Условия, которые нельзя нарушать

1. **Ровно два `-v`:** хранилище → `/home/agent` и текущая папка → `/workspace`. Никаких
   дополнительных монтирований (`~/.ssh`, `~/.gitconfig`, `docker.sock`, `$HOME`):
   каждое из них разрушает идею «доступна только эта папка». Файлы плагинов (например,
   kubeconfig kind) живут внутри хранилища.
2. **Секреты не попадают в образ и в аргументы команды.** В Dockerfile нет `ARG`/`ENV` с
   ключами. `ANTHROPIC_API_KEY` передаётся только как `-e ANTHROPIC_API_KEY` (по имени).
   Токены плагинов (например, kind) пишутся только в файлы с правами 600; секрет в контейнер
   плагин передаёт по имени переменной (`plugin_add_env ИМЯ`), без значения в аргументах.
3. **Изоляция живёт во флагах `docker run`, а не в образе:** `--user`, `--cap-drop=ALL`,
   `--security-opt no-new-privileges`. Не добавлять `--privileged`, не убирать `--user`.
4. **Защита от запуска не из той папки остаётся:** Linux — отказ из `~` и `/` (обход
   только через `AGENTCELL_ALLOW_ANY_DIR=1`); macOS — только внутри `PROJECT_DIR`.
5. **Обновление = пересборка образа с `--pull --no-cache`.** Иначе Docker возьмёт из кэша
   старый слой с установкой Claude Code.
6. **Пути внутри контейнера (`/workspace`, `/home/agent`) задаются только в скрипте запуска.**
   В Dockerfile их нет.
7. **Скрипты совместимы с bash 3.2** (системный bash в macOS): без `mapfile`, без
   ассоциативных массивов. Массивы, которые разворачиваются через `"${arr[@]}"`, никогда
   не бывают пустыми в этот момент (иначе `set -u` в bash 3.2 падает); для `PROJECT_DIRS`
   есть отдельный счётчик `PROJECT_DIR_COUNT`.
8. **Хранилище общее для всех проектов,** не привязано к конкретной папке.
9. **macOS: в VM `agentcell` смонтированы только папки `PROJECT_DIR` и хранилище.**
   Домашняя папка и папки из `SENSITIVE_NAMES` — никогда. Конфиг не лежит внутри
   хранилища (агент не должен его видеть). Папки не пересекаются друг с другом и с
   хранилищем (`check_no_overlap`): Colima сравнивает пути как строки, поэтому `~/src` и
   `~/src2` для неё пересекаются. «Секретные» папки проверяются без учёта регистра.
   Проверка «по факту» (`vm_check_home_hidden`) выполняется при каждом запуске.
10. **macOS: все вызовы docker — через функцию `dkr`** (контекст `colima-agentcell`).
    Пользовательский docker-контекст не меняется (`colima start --activate=false`).
11. **В скрипте запуска нет вопросов к пользователю.** Всё, что требует решения человека, —
    ошибка с готовой командой. Иначе ломается запуск из cron.
12. **Ядро ничего не знает про конкретные плагины.** В `scripts/agentcell` нет кода kind: оно
    только загружает плагины и вызывает три функции (`<имя>_check`, `<имя>_prepare`,
    `<имя>_status`). Плагин без включающей переменной (`AGENTCELL_<ПЛАГИН>_*`) ничего не
    делает.
13. **Плагин меняет контейнер только через `plugin_add_network` и `plugin_add_env`.** Монтирования,
    привилегии и другие флаги docker плагину недоступны; имена переменных проверяются.
    Код плагинов лежит в `~/.config/agentcell/plugins/`, вне папок, видимых контейнеру и VM.
14. **Плагины не должны ломать друг друга:** свои имена (`<имя>_...`,
    `AGENTCELL_<ПЛАГИН>_...`), несовместимость — в поле `CONFLICTS` манифеста и в документе
    плагина.
15. **Сообщения скрипта запуска — в stderr,** stdout принадлежит claude (режим `-p`), кроме
    ответа `--vm-status`.
16. **Стандартный ввод принадлежит claude.** Вызовы `colima` (особенно `colima ssh`) идут с
    `</dev/null`, иначе данные из пайпа теряются.
17. **Опция `BLOCK_HOST_ACCESS` по умолчанию выключена.** Правило межсетевого экрана ставит
    `vm_block_host_access` в конце `vm_start` и только при `BLOCK_HOST_ACCESS=1`; не удалось —
    запуск прекращается, а не продолжается без защиты.
18. **Проверка и старт VM — под замком `vm_lock`:** одновременные запуски не должны стартовать
    одну VM дважды. Длинный вывод `colima start/stop` скрыт (`colima_quiet`) и показывается только
    при ошибке.

### Где что менять

| Что нужно изменить | Где править |
|---|---|
| Версию Claude Code | `CLAUDE_CODE_VERSION` при запуске `scripts/install.sh` или `ARG` в `Dockerfile` |
| Версию kubectl | `KUBECTL_VERSION` при запуске `scripts/install.sh --with kind` или `ARG` в `Dockerfile` |
| Набор инструментов в образе | `Dockerfile` (добавить `apt-get install`) |
| Флаги изоляции, пути в контейнере, имя образа, переменные | `scripts/agentcell` |
| Ключи конфига, проверки папок, список `SENSITIVE_NAMES` | `scripts/agentcell` (`load_config`, `check_*`) и шаблон в `scripts/install.sh` |
| Управление VM | `scripts/agentcell` (функции `vm_*`, `cmd_vm_*`) |
| Права агента в kind, срок токена | `plugins/kind/plugin.sh` (`kind_apply_rbac`, `kind_apply_admin_mode`), настройки `plugins/kind/config.example` |
| Новый плагин | `plugins/<имя>/` и `docs/plugins/<имя>.md`; правила в `docs/PLUGINS.md` |
| Как плагины загружаются, их API (`plugin_*`) | `scripts/agentcell` (раздел «Плагины») и `scripts/install.sh` |
| Процесс установки и обновления | `scripts/install.sh` |

### Правила работы над проектом

- Комментарии в коде и вся документация — на русском. Всё, что скрипты печатают в терминал
  (сообщения, ошибки), — на английском.
- Код должен быть простым и понятным новичку: понятность важнее изящества.
- После любого изменения сверьте с кодом `README.md`, `docs/` и комментарии. Они должны
  описывать текущее состояние, а не прошлое.
- Не оставляйте неиспользуемых функций, файлов и зависимостей. Исключение: функции для
  плагинов (`plugin_add_network`, `plugin_add_env`, `plugin_read_config`) вызываются из
  `plugin.sh`, а три функции плагина (`<имя>_check`, `<имя>_prepare`, `<имя>_status`) ядро
  вызывает по имени, поэтому поиск вызовов их не находит.
- Команды `docker`, `colima` и `kind` выполняет владелец проекта и присылает вывод. ИИ-агент
  их не запускает: он проверяет скрипты статически (`bash -n`) и может прогнать их в
  изолированной среде с поддельными `docker` и `colima` и поддельным `HOME`, не
  затрагивая настоящую систему.
- Локальные заметки и списки проверок ИИ-агент ведёт в папке `.notes/`: она перечислена в
  `.gitignore` и в git не попадает.
- Коммиты и отправку в git делает только владелец проекта.
- Файл результата проверочной сборки всегда один и тот же — `agentcell.out` — и он
  перечислен в `.gitignore`.
