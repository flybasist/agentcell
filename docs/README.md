# Документация agentcell

agentcell запускает Claude Code в Docker-контейнере, который видит только одну папку проекта
и небольшое хранилище для входа в аккаунт. Это удобная утилита из скрипта запуска,
скрипта установки и Dockerfile.

## Для ИИ-агентов и разработчиков

Эта страница — точка входа. Читайте её первой, затем нужный файл из оглавления.
Не сканируйте весь репозиторий заново: карта ниже достаточна.

### Что где лежит

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ: `node:24` + `npm install -g @anthropic-ai/claude-code`, `ENTRYPOINT ["claude"]`. Файлы проекта в образ не копируются. |
| `scripts/agentcell` | Скрипт запуска на хосте (копируется в `~/bin`): проверки и `docker run` с изоляцией. |
| `scripts/install.sh` | Сборка образа (`--pull --no-cache`) и установка команды `agentcell`. Он же — обновление. |
| `README.md` | Краткое описание для человека. |
| `CHANGELOG.md` | История изменений. |
| `docs/` | Вся остальная документация. Должна всегда соответствовать коду. |

### Условия, которые нельзя нарушать

1. **Ровно два `-v`:** `$STATE_DIR:/home/agent` и `$PROJECT_DIR:/workspace`. Никаких
   дополнительных монтирований (`~/.ssh`, `~/.gitconfig`, `docker.sock`, `$HOME`):
   каждое из них разрушает идею «доступна только эта папка».
2. **Секреты не попадают в образ и в аргументы команды.** В Dockerfile нет `ARG`/`ENV` с
   ключами. `ANTHROPIC_API_KEY` передаётся только как `-e ANTHROPIC_API_KEY` (по имени).
3. **Изоляция живёт во флагах `docker run`, а не в образе:** `--user`, `--cap-drop=ALL`,
   `--security-opt no-new-privileges`. Не добавлять `--privileged`, не убирать `--user`.
4. **Защита от запуска из `~` и `/` остаётся** (обход только через `AGENTCELL_ALLOW_ANY_DIR=1`).
5. **Обновление = пересборка образа с `--pull --no-cache`.** Иначе Docker возьмёт из кэша
   старый слой с установкой Claude Code.
6. **Пути внутри контейнера (`/workspace`, `/home/agent`) задаются только в скрипте запуска.**
   В Dockerfile их нет.
7. **Скрипты совместимы с bash 3.2** (системный bash в macOS): без `mapfile`, без
   ассоциативных массивов, массив `DOCKER_ARGS` никогда не бывает пустым (иначе `set -u`
   в bash 3.2 падает).
8. **Хранилище общее для всех проектов,** не привязана к конкретной папке.

### Где что менять

| Что нужно изменить | Где править |
|---|---|
| Версию Claude Code | `CLAUDE_CODE_VERSION` при запуске `scripts/install.sh` или `ARG` в `Dockerfile` |
| Набор инструментов в образе | `Dockerfile` (добавить `apt-get install`) |
| Флаги изоляции, пути в контейнере, имя образа, переменные | `scripts/agentcell` |
| Процесс установки и обновления | `scripts/install.sh` |

### Правила работы над проектом

- Комментарии в коде и вся документация — на русском. Всё, что скрипты печатают в терминал
  (сообщения, ошибки), — на английском.
- Код должен быть простым и понятным новичку: понятность важнее изящества.
- После любого изменения сверьте с кодом `README.md`, `docs/` и комментарии. Они должны
  описывать текущее состояние, а не прошлое.
- Не оставляйте неиспользуемых функций, файлов и зависимостей.
- Команды `docker` (сборку, запуск, остановку) выполняет владелец проекта и присылает вывод.
  ИИ-агент docker сам не запускает: проверяйте скрипты через `bash -n`.
- Коммиты и отправку в git делает только владелец проекта.
- Файл результата проверочной сборки всегда один и тот же — `agentcell.out` — и он
  перечислен в `.gitignore`.
