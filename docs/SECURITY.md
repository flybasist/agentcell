# Безопасность

## Слои защиты

```
Мак / компьютер           <- ваши ключи, доступы, все файлы
 └─ VM agentcell (macOS)  <- видит только PROJECT_DIR и хранилище
     └─ контейнер         <- видит только текущий проект и хранилище
```

Контейнер — основная граница. VM на macOS — вторая: она решает, что достанется тому,
кто выберется из контейнера (через уязвимость ядра или Docker, либо через
привилегированный под в кластере плагина, например kind с правами cluster-admin).

## Что защищено

- Агент не видит домашнюю папку, SSH-ключи, другие проекты и сокет Docker.
- Процесс запущен не от root, без Linux-capabilities и без возможности повысить привилегии.
- Контейнер удаляется после каждого запуска.
- API-ключ передаётся по имени переменной: он не попадает ни в образ, ни в аргументы команды
  (то есть не виден в списке процессов).
- **macOS:** даже при побеге из контейнера в VM домашней папки там нет: только папки
  `PROJECT_DIR` и хранилище. Скрипт запуска проверяет это по факту при каждом запуске.
- **Плагины** не могут ослабить изоляцию контейнера: ядро даёт им только сеть и переменные
  окружения, без монтирований и привилегий (см. раздел «Плагины»). Что защищает плагин kind
  (права агента в кластере, чужие кластеры), описано в [plugins/kind.md](plugins/kind.md).

## Что НЕ защищено

- **Проект доступен на запись целиком.** Агент может удалить или испортить в нём что
  угодно. Держите проект в git и делайте коммит перед рискованными задачами.
- **Git-хуки.** Агент может записать скрипт в `.git/hooks` проекта. Когда вы потом
  выполните `git commit` на своём компьютере, этот скрипт запустится уже вне контейнера.
  Перед коммитом после работы агента полезно проверить `ls .git/hooks`.
- **Сервисы на вашем Маке (по умолчанию).** Контейнер может обращаться к тому, что слушает только
  localhost на Маке (локальные базы, панели, dev-серверы): проверено, что `host.docker.internal`
  и `host.lima.internal` (адрес 192.168.5.2) доходят до `127.0.0.1` Мака. Закрыть этот доступ
  можно опцией `BLOCK_HOST_ACCESS=1` в конфиге (см. «Закрыть доступ к Маку» ниже). Сервисы,
  открытые в локальную сеть (слушают не только localhost), опция не закрывает: они и так
  доступны любому устройству в сети.
- **Сеть открыта.** Она нужна самому Claude, но агент может обращаться и к другим адресам,
  включая всё, что доступно вашему компьютеру по сети.
- **Токен входа лежит в хранилище** и доступен процессам внутри контейнера. Не запускайте
  автономного агента на недоверенных проектах и по инструкциям из внешних источников.
- **macOS, побег в VM:** открывает все папки `PROJECT_DIR` (не только текущий проект) и
  хранилище. Держите список коротким.
- **Linux:** VM нет. Побег из контейнера — это сразу ваш компьютер.
- **Docker-образ и Claude Code — внешнее ПО.** Его безопасность определяют их авторы.

## Плагины

Плагин — код, который выполняется на вашем компьютере с вашими правами при каждом запуске
agentcell. Поэтому:

- ставьте только плагины, которым доверяете, и читайте их код (он короткий);
- код плагинов лежит в `~/.config/agentcell/plugins/`: этой папки нет ни в контейнере, ни в
  VM, агент изменить его не может;
- плагин не может добавить контейнеру монтирования, привилегии, сменить пользователя или
  передать любой другой флаг docker: ядро разрешает ему только `plugin_add_network` и
  `plugin_add_env`;
- плагин всё же может делать на хосте то, что делает любая ваша команда (вызывать docker в
  VM, писать файлы в хранилище), поэтому каждый новый плагин проверяется вместе с ядром.

Опасные режимы конкретного плагина описаны в его документе. Для kind это cluster-admin:
ноды kind — привилегированные контейнеры, и агент с такими правами может выйти из кластера в
VM, поэтому режим включается только на одну сессию ([plugins/kind.md](plugins/kind.md)).
Общие правила: [PLUGINS.md](PLUGINS.md).

## Рекомендации

- Режим без подтверждений (`--dangerously-skip-permissions`) используйте только в
  проверенных проектах и после коммита.
- Запускайте `agentcell` строго из папки проекта, а не из родительской папки с несколькими
  проектами. Если вы запустили из корня `PROJECT_DIR` без `.git`, скрипт предупредит.
- macOS: перечисляйте в `PROJECT_DIR` только папки, с которыми работает агент; не
  монтируйте папки, где лежат `.env` с боевыми ключами.
- На виртуальной машине перед тяжёлой задачей полезно сделать снимок машины.

## Закрыть доступ к Маку (опция)

В конфиге `~/.config/agentcell/config` (macOS):

```
BLOCK_HOST_ACCESS=1
```

затем `agentcell --vm-apply`. В VM ставится правило межсетевого экрана (цепочка `DOCKER-USER`):
любой трафик контейнеров к адресу хоста (`host.lima.internal`) отклоняется сразу. Интернет, DNS,
доступ к другим контейнерам и к кластерам плагинов не затрагиваются. Правило действует и на
поды кластеров плагинов (проверено на kind), поскольку их трафик идёт через ту же VM. Оно не переживает перезапуск VM, поэтому скрипт запуска
ставит его заново при каждом старте VM; если поставить не удалось, запуск прекращается с ошибкой.
По умолчанию опция выключена: она сломает всё, что агент должен брать с Мака (локальный
dev-сервер, база для тестов). `agentcell --vm-status` показывает, включена ли она.

## Как можно ужесточить (пока не включено)

Эти флаги `docker run` можно добавить в `scripts/agentcell`, но они могут мешать обычной
работе, поэтому по умолчанию их нет:

| Флаг | Что даёт | Чем рискуем |
|---|---|---|
| `--read-only` вместе с `--tmpfs /tmp` | корневая файловая система контейнера только для чтения | часть инструментов пишет в другие места и перестанет работать |
| `--pids-limit N` | ограничение числа процессов | слишком малое значение ломает сборки |
| `--memory N`, `--cpus N` | ограничение памяти и процессора | долгие задачи могут упасть |
| отдельная сеть с фильтром | ограничение исходящих адресов | требует настройки вне agentcell |
