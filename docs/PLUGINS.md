# Плагины

Ядро agentcell делает одно: запускает Claude Code в контейнере, который видит одну папку.
Всё, что нужно не каждому, подключается плагинами. Сейчас плагин один: [kind](plugins/kind.md)
(доступ агента к локальному kind-кластеру).

Плагин — это небольшой кусок bash-кода, который ядро загружает при запуске. Он не
меняет изоляцию: добавить контейнеру он может только сеть и переменные окружения.

## Как поставить и убрать

```bash
./scripts/install.sh --with kind     # поставить (флаг можно повторять)
./scripts/install.sh --without kind  # убрать вместе с настройками
./scripts/install.sh                 # обновить ядро и код уже установленных плагинов
```

- **Установленный плагин включён:** отдельного списка нет. Что лежит в
  `~/.config/agentcell/plugins/`, то и загружается.
- **Файлы плагина** лежат в `~/.config/agentcell/plugins/<имя>/`: `plugin.sh` (код),
  `plugin.conf` (манифест) и `config` (ваши настройки, если они есть).
- **Повторная установка** обновляет код и манифест, но **не трогает `config`**. Настройки
  берутся из примера (`config.example`) только при первой установке.
- **`--without` удаляет** папку плагина вместе с настройками.
- **Образ пересобирается** при каждой установке: плагину может понадобиться инструмент
  (например, kubectl для kind). Образ собирается с тем, что нужно установленным плагинам.
- Перед установкой скрипт проверяет, что плагин существует, что в его коде нет
  синтаксических ошибок (`bash -n`), что он поддерживает вашу систему и что он не
  конфликтует с уже установленными.

## Как плагин включается в сессии

Установленный плагин не работает в каждой сессии: его включают переменные окружения вида
`AGENTCELL_<ПЛАГИН>_*`. Для kind:

```bash
AGENTCELL_KIND_CLUSTER=lab agentcell
```

Без этих переменных плагин ничего не делает: не обращается ни к docker, ни к кластеру и
ничего не добавляет контейнеру. Ядро аргументы плагинов не разбирает, поэтому флаги `claude`
никогда не путаются с настройками плагина.

## Устройство плагина

В репозитории плагин — папка `plugins/<имя>/`:

| Файл | Назначение |
|---|---|
| `plugin.conf` | Манифест (поля ниже). Его читают `scripts/install.sh` и `scripts/agentcell`. |
| `plugin.sh` | Код плагина. Его не запускают сами: ядро загружает его командой `source`. |
| `config.example` | Пример настроек плагина (необязателен). |

Описание плагина для людей лежит в `docs/plugins/<имя>.md`. Имя плагина может состоять
только из `a-z` и `0-9`: по нему называются функции.

### Манифест `plugin.conf`

Строки `КЛЮЧ=значение`. Строки с `#` — комментарии.

| Поле | Что значит |
|---|---|
| `NAME` | имя плагина (как папка) |
| `SUMMARY` | одна строка, по-английски: её печатает установка |
| `PLATFORMS` | где работает: `macos`, `linux` или оба через пробел; пусто — везде |
| `CONFLICTS` | имена плагинов, с которыми он несовместим, через пробел |
| `IMAGE_ARGS` | что нужно образу, как аргументы сборки `КЛЮЧ=значение` (см. ниже) |

### Три функции плагина

Здесь `<имя>` — имя плагина. Ядро требует все три: плагин, у которого их нет,
не загружается и запуск прекращается с ошибкой.

| Функция | Когда вызывается | Что делает |
|---|---|---|
| `<имя>_check` | при каждом запуске, до подготовки | проверяет условия (кластер, образ, настройки); при ошибке вызывает `die`; ничего не меняет |
| `<имя>_prepare` | при каждом запуске, после всех `check` | делает подготовку перед запуском контейнера и подключает его к плагину (сеть, переменные) |
| `<имя>_status` | при `agentcell --vm-status` (macOS) | печатает строки о плагине |

Функции вызываются для каждого установленного плагина при каждом запуске, поэтому первым
делом они проверяют, включён ли плагин в этой сессии, и если нет, сразу выходят
(`return 0`). Порядок такой: сначала `check` у всех плагинов, потом `prepare` у всех.

### Что плагину доступно

Плагин работает в процессе ядра, поэтому ему доступны его функции и переменные:

- функции: `die` (ошибка и выход), `info`, `warn`, `dkr` (docker в VM agentcell на macOS),
  `real_dir`, `profile_state`;
- переменные: `IMAGE`, `STATE_REAL`, `CELL_HOME`, `CELL_WORKDIR`, `CONFIG_DIR`,
  `PLUGINS_DIR`, `VM_PROFILE`, `DOCKER_CONTEXT_NAME`.

Менять контейнер плагин может только тремя функциями ядра:

| Функция | Что делает |
|---|---|
| `plugin_add_network <сеть>` | подключает контейнер к docker-сети |
| `plugin_add_env ИМЯ=значение` | передаёт переменную в контейнер |
| `plugin_add_env ИМЯ` | то же, но по имени: значение берётся из окружения хоста и не попадает в аргументы команды (так передают секреты) |

Имя переменной: заглавные буквы, цифры и `_`, иначе запуск прекращается. Монтирования,
привилегии и любые другие флаги docker плагину недоступны: на них держится изоляция.

Настройки плагина читает функция `plugin_read_config <плагин> КЛЮЧ [КЛЮЧ...]`: она
разбирает файл настроек (ниже) и кладёт значения в переменные с теми же именами.

## Настройки плагина

У плагина свой файл `~/.config/agentcell/plugins/<имя>/config`: строки `КЛЮЧ=значение`,
как в основном конфиге (без пробелов вокруг `=` и без кавычек, `#` — комментарий). Лишний
ключ или строка не в формате — ошибка. Файла нет — действуют значения по умолчанию.

Изменения вступают в силу при следующем запуске agentcell, перезапуск VM не нужен. Общий
конфиг agentcell плагин не читает и не меняет.

## Образ и инструменты плагина

Если плагину нужен инструмент в образе, в манифесте пишут `IMAGE_ARGS=КЛЮЧ=значение`
(например, `WITH_KUBECTL=1`). Установка передаёт это в сборку образа как `--build-arg`, а в
`Dockerfile` есть соответствующий `ARG`. Инструмент ставится только по этому аргументу, так
что без плагина образ остаётся маленьким. Образ получает метку (например,
`agentcell.kubectl=1`), и плагин перед запуском проверяет её: если образ собран без
инструмента, плагин пишет точную команду пересборки.

Новому плагину с новым инструментом нужны три вещи: `ARG` в `Dockerfile`, метка на
образе и проверка метки в `<имя>_check`.

## Совместимость плагинов

Плагины не должны ломать друг друга. Для этого:

- каждый плагин использует только свои имена: функции `<имя>_...`, переменные окружения
  `AGENTCELL_<ПЛАГИН>_...`, файлы `agentcell-<имя>...`, ресурсы с понятным префиксом;
- если плагины всё же нельзя использовать вместе, это пишут в манифесте
  (`CONFLICTS=другой`) и в документе плагина. Установка и запуск тогда отказывают с
  сообщением: «чтобы использовать B, уберите A» (`./scripts/install.sh --without A`).

Сейчас плагин один, поэтому известных конфликтов нет.

## Платформы

В манифесте `PLATFORMS` перечисляет системы, где плагин работает. Установка на другой
системе отказывает с понятным сообщением. Уже установленный плагин на неподходящей системе
пропускается с предупреждением, запуск при этом не прерывается.

## Безопасность

- **Плагин выполняется на вашем компьютере с вашими правами** при каждом запуске agentcell.
  Ставьте только плагины, которым доверяете, и читайте их код: он короткий.
- **Агент не может изменить код плагина:** папки `~/.config/agentcell/plugins/` нет ни в
  контейнере, ни в VM.
- **Плагин не может ослабить изоляцию контейнера:** монтирования, привилегии, смена
  пользователя и прочие флаги docker ему недоступны (ядро даёт ему только сеть и
  переменные).
- **Плагин может делать на хосте то, что делает любая ваша команда:** вызывать docker в VM,
  писать файлы в хранилище. Поэтому любой новый плагин нужно проверять вместе с ядром.

## Как написать свой плагин

1. Создайте `plugins/<имя>/` (имя: `a-z` и `0-9`) с файлами `plugin.conf` и `plugin.sh`.
2. В `plugin.sh` определите три функции: `<имя>_check`, `<имя>_prepare`, `<имя>_status`.
   Первым делом они проверяют, включён ли плагин в сессии (ваша переменная
   `AGENTCELL_<ПЛАГИН>_*`), и если нет, выходят.
3. Всё, что плагин добавляет контейнеру, делайте через `plugin_add_network` и
   `plugin_add_env`.
4. Если нужны настройки, положите `config.example` и читайте их через `plugin_read_config`.
5. Если нужен инструмент в образе, добавьте `ARG` в `Dockerfile`, метку и проверку метки.
6. Напишите `docs/plugins/<имя>.md` и добавьте строку в оглавление `docs/README.md`. Если у
   плагина есть внешние зависимости, дополните `docs/CREDITS.md`.
7. Проверьте: `bash -n plugins/<имя>/plugin.sh`, установку (`--with` и `--without`),
   запуск без плагина и с ним.

Минимальный пример (`plugins/hello/plugin.sh`):

```bash
# Плагин hello: передаёт в контейнер переменную HELLO_NAME.
# Включается переменной AGENTCELL_HELLO_NAME.

hello_check() {
    :
}

hello_prepare() {
    [ -n "${AGENTCELL_HELLO_NAME:-}" ] || return 0
    plugin_add_env "HELLO_NAME=$AGENTCELL_HELLO_NAME"
}

hello_status() {
    echo "Plugin hello: installed"
}
```

и манифест `plugins/hello/plugin.conf`:

```
NAME=hello
SUMMARY=Passes HELLO_NAME into the container
PLATFORMS=macos linux
CONFLICTS=
IMAGE_ARGS=
```
